# GitHub account sign-in

NikGapps uses GitHub's OAuth device flow. Register a GitHub OAuth App for NikGapps and enable **Device Flow** in its settings. Set `NIKGAPPS_CLIENT_ID` in your user-level Gradle properties (`~/.gradle/gradle.properties`), or set the `NIKGAPPS_CLIENT_ID` environment variable. Both GitHub Actions workflows read the `NIKGAPPS_CLIENT_ID` repository secret. The client ID is public and is embedded in the APK. The OAuth client secret is not required for device flow and must not be embedded in the app or committed to the repository.

The flow requests the `repo` scope because the GitHub API helper can write to a private repository. On the welcome screen, select **Continue with GitHub**. The app requests a one-time code, copies it, and opens GitHub in the browser; paste the code and authorize the app. The app polls at GitHub's requested interval until authorization succeeds, the code expires, or the dialog is closed. The token is saved to the existing GitHub preference. Signing out deletes the local token but remembers the username for a welcome-back prompt; reconnecting still requires a new device code. Alternatively, open **Settings** from the welcome screen, select **Account → GitHub token**, and save a personal access token. The app verifies it with GitHub before allowing entry. Clearing the token in settings signs out and returns to the welcome screen. For repository file writes with a fine-grained token, grant **Contents: Read and write** on the target repository.

Local builds without `NIKGAPPS_CLIENT_ID` show a setup message and retain manual token entry. Release and development workflows fail if the client ID is missing, preventing publication of an APK with sign-in disabled.
